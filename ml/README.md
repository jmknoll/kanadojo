# KanaScript ML Pipeline

On-device handwriting grading for Type B (Romaji → Kana) quizzes.

## Overview

Grading uses a two-stage pipeline:

1. **CNN Classifier** — trained on font renders of all 92 main kana. Used at training time to generate a confusion matrix identifying which characters look similar.
2. **Embedding Model** — metric-learning model trained using the confusion matrix to produce a 128-d embedding space where visually similar kana cluster together. This is the model deployed to iOS for runtime grading.

```
Font renders → CNN Classifier → Confusion Matrix → Embedding Model → iOS grading
```

At runtime, the user's drawn strokes are embedded and compared to the target character's prototype cluster. The L2 distance determines the quality score (0–1).

## Step-by-Step: Full Pipeline

### Phase A — Font Dataset

**Step 1: Download fonts**

```bash
python3 ml/scripts/download_fonts.py
```

Output: `ml/data/fonts/` — 25 free Japanese fonts.

**Step 2: Render font images**

```bash
python3 ml/scripts/render_fonts.py
```

Renders all 92 main kana (hiragana + katakana) in each font with random geometric distortions (scale, shear, affine). Output: `ml/data/font_renders/`.

---

### Phase B — Train CNN Classifier

**Step 3: Train**

```bash
python3 ml/scripts/train.py
```

Default: 60 epochs, batch size 64, Adam + CosineAnnealingLR. Saves `ml/models/best_model.pt`.

Optional flags:
```bash
python3 ml/scripts/train.py --epochs 80 --batch-size 32 --lr 5e-4
```

**Step 4: Evaluate**

```bash
python3 ml/scripts/evaluate.py
```

Prints top-1 accuracy and the 20 worst classes. Saves `confusion_matrix.png` and `per_class_accuracy.json`.

**Gate: ≥95% test accuracy before proceeding.**

---

### Phase C — Confusion Matrix → Confusable Pairs

**Step 5: Extract confusable pairs**

```bash
python3 ml/scripts/compute_confusion_matrix.py
```

Runs all font renders through the trained CNN, computes mean softmax per class (within-script only — hiragana vs hiragana, katakana vs katakana). Saves the top-4 most confusable characters per class to `ml/data/confusable_pairs.json`. This file feeds the embedding model's hard-negative training strategy.

---

### Phase D — Train Embedding Model

**Step 6: Extract stroke order data**

```bash
python3 ml/scripts/extract_stroke_order.py
```

Parses KanjiVG stroke order from `StrokeOrder.swift` and saves to `ml/data/stroke_order.json`. Used to generate partial-stroke negative samples.

**Step 7: Generate negative training samples**

```bash
python3 ml/scripts/generate_incorrect_samples.py
```

Generates three categories of negative samples per character:
- **Random** — random bezier strokes on a blank canvas
- **Confusable** — font renders of visually similar characters (from `confusable_pairs.json`)
- **Partial** — renders with 1 to n-1 strokes (from `stroke_order.json`)

Output: `ml/data/incorrect_samples/`.

**Step 8: Train the embedding model**

```bash
python3 ml/scripts/train_embedding.py
```

Trains a metric-learning model (ArcFace loss) that maps 64×64 kana images to a 128-d L2-normalized embedding space. Characters of the same class cluster tightly; confusable characters remain separated. Saves `ml/models/best_embedder.pt`.

**Step 9: Compute prototypes**

```bash
python3 ml/scripts/compute_prototypes.py
```

Embeds all font renders through `best_embedder.pt`. Computes per-character prototype (mean embedding) and radius (95th-percentile L2 distance from prototype). Output: `KanaFlow/KanaFlow/Models/kana_prototypes.json`.

---

### Phase E — Export to Core ML

**Step 10: Convert to Core ML**

Requires macOS with Xcode and `coremltools`:

```bash
python3 ml/scripts/convert_embedding_to_coreml.py
```

Exports the embedding model (features + GAP + embed + L2-norm, without ArcFace head) to Core ML. Output: `KanaFlow/KanaFlow/Models/KanaEmbedderModel.mlpackage`.

Regenerate the Xcode project after adding model files:
```bash
xcodegen generate
```

## iOS Integration

The iOS app uses `KanaEmbeddingScorer` (`KanaFlow/Logic/KanaEmbeddingScorer.swift`) to grade user drawings at runtime:

1. User strokes are rendered to a 64×64 grayscale bitmap (ink=111/255, bg=200/255)
2. The bitmap is passed through `KanaEmbedderModel.mlpackage` → 128-d embedding
3. L2 distance to the target character's prototype is computed
4. Score = `max(0, 1 − distance / (radius × radiusScale))`
5. Pass threshold: score ≥ 0.50

If the model files are not present (e.g. in a fresh clone before running the pipeline), grading falls back to manual self-grading.

## Preprocessing Contract

The Python training pipeline and Swift inference must agree exactly:

| Property | Value |
|---|---|
| Canvas size | 64×64 px |
| Ink colour | 111 / 255 (dark grey) |
| Background colour | 200 / 255 (light grey) |
| Normalisation | pixel / 255 → float32 |
| Embedding dim | 128, L2-normalized |
| Pass threshold | score ≥ 0.50 |
| Radius scale | 3.0× (accounts for handwriting vs font variability) |

## Model Architecture

### CNN Classifier (training only)

4-block CNN: Conv→BN→ReLU→MaxPool (×4) → GlobalAvgPool → Dropout(0.4) → FC(92)

| Layer | Output shape |
|---|---|
| Input | 1 × 64 × 64 |
| Block 1 (32ch) | 32 × 32 × 32 |
| Block 2 (64ch) | 64 × 16 × 16 |
| Block 3 (128ch) | 128 × 8 × 8 |
| Block 4 (256ch) | 256 × 4 × 4 |
| GlobalAvgPool | 256 |
| FC | 92 |

### Embedding Model (deployed to iOS)

Same 4-block feature extractor, without classification head:

| Layer | Output |
|---|---|
| Feature extractor (4 conv blocks) | 256-d |
| GlobalAvgPool | 256-d |
| FC (256→128) | 128-d |
| L2 normalization | 128-d unit vector |

Trained with ArcFace loss (s=16.0, m=0.35) on 92 kana classes.
