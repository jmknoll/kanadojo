# KanaFlow ML Pipeline

On-device CNN classifier for kana handwriting recognition.
Input: 64×64 grayscale bitmap of user strokes → Output: softmax probability over 214 kana classes.

## Overview

The classifier covers all 214 kana characters used in the app:

| Source | Classes | Images |
|---|---|---|
| ETL4 (hiragana main) | 46 | ~120–240 each |
| ETL5 (katakana main) | 46 | ~208–416 each |
| Synthetic dakuten | 50 | same count as base char |
| Synthetic combinations | 72 | 300 each |

## Prerequisites

**Recommended: use [uv](https://github.com/astral-sh/uv) for fast, isolated dependency management.**

```bash
# Install uv (if not already installed)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Create a virtual environment and install all dependencies
cd ml
uv venv
source .venv/bin/activate    # macOS/Linux
uv pip install -r requirements.txt
```

Or with plain pip in a venv:

```bash
cd ml
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Required packages: `torch`, `albumentations`, `Pillow`, `numpy`, `matplotlib`

> **Note:** `coremltools` is only needed for the Core ML export step (Phase D) and requires macOS with Xcode. Install it separately when you're ready to export:
> ```bash
> uv pip install coremltools
> ```

Once the venv is active, all `python3 ml/scripts/...` commands below should be run from the repo root (`KanaFlow/`).

## Step-by-Step: Generate Synthetic Data & Train

Run all commands from the repo root (`KanaFlow/`).

### Phase A — Synthesise missing classes

**Step 1: Build dakuten classes** (voiced/semi-voiced — 50 classes)

Overlays programmatic ゛/゜ marks on ETL4/5 base character images.

```bash
python3 ml/scripts/build_dakuten.py
```

Output: `ml/data/synthetic/dakuten/` — one subdirectory per dakuten character.

**Step 2: Build combination classes** (72 classes, 300 images each)

Composites left + right ETL components onto a 64×64 canvas matching the app's drawing layout.

```bash
python3 ml/scripts/build_combinations.py
```

Output: `ml/data/synthetic/combinations/` — one subdirectory per combination character.

---

### Phase B — Train the model

```bash
python3 ml/scripts/train.py
```

Default: 60 epochs, batch size 64, Adam + CosineAnnealingLR.
Checkpoints are saved to `ml/models/best_model.pt` (best val loss) and `ml/models/last_model.pt`.

Optional flags:
```bash
python3 ml/scripts/train.py --epochs 80 --batch-size 32 --lr 5e-4
```

Training progress is printed per epoch and saved to `ml/models/training_history.json`.

---

### Phase C — Evaluate

```bash
python3 ml/scripts/evaluate.py
```

Prints top-1 accuracy and the 20 worst-performing classes.
Saves `ml/models/per_class_accuracy.json` and `ml/models/confusion_matrix.png`.

**Gate: ≥95% test-set accuracy before exporting to Core ML.**

---

### Phase D — Export to Core ML

Requires macOS with Xcode and `coremltools`:

```bash
pip install coremltools
python3 ml/scripts/convert_to_coreml.py
```

Outputs:
- `KanaFlow/KanaFlow/Models/KanaClassifier.mlpackage`
- `KanaFlow/KanaFlow/Models/kana_labels.json`

Then regenerate the Xcode project and build:
```bash
xcodegen generate
```

## Preprocessing Contract

The Python training pipeline and the Swift `KanaRecognizer` must agree exactly:

| Property | Value |
|---|---|
| Canvas size | 64×64 px |
| Colour space | Grayscale |
| Data type | float32 |
| Range | [0, 1] (uint8 / 255) |
| Ink | dark (low values) |
| Background | white (1.0) |
| Input tensor shape | (1, 1, 64, 64) — batch × channel × H × W |

---

## Model Architecture

4-block CNN: Conv→BN→ReLU→MaxPool (×4) → GlobalAvgPool → Dropout(0.4) → FC(214)

| Layer | Output shape |
|---|---|
| Input | 1 × 64 × 64 |
| Block 1 (32ch) | 32 × 32 × 32 |
| Block 2 (64ch) | 64 × 16 × 16 |
| Block 3 (128ch) | 128 × 8 × 8 |
| Block 4 (256ch) | 256 × 4 × 4 |
| GlobalAvgPool | 256 |
| FC | 214 |

~3M trainable parameters.
